# V8 SDKs

[v8-version.cmake](../v8-version.cmake) pins V8 **13.6.233.17**, its source commit
and depot_tools revision. [build-v8.cmake](../scripts/build-v8.cmake) uses
depot_tools, gclient, GN and Ninja, independently of the ordinary vcpkg packages.
This is a pinned historical V8 release, not Node.js or an addon build.

For publication and reuse, see the [release guide](v8-release.md).

## Targets

| Triplet | Build host | Library / execution mode | Consumer validation |
| --- | --- | --- | --- |
| x64-windows-star | Windows, VS 2022 C++ tools and Windows SDK debugging tools | DLL, JIT, WebAssembly, /MD or /MDd | Execute |
| arm64-osx-star | Apple Silicon, full Xcode; macOS 13.0+ | dylib, JIT, WebAssembly | Execute |
| arm64-android-star | Linux x64, NDK 30.0.16248370; API 28 | .so, JIT, WebAssembly, c++_shared | Compile/link; optional device execution |
| x64-android-star | Same host/NDK/API | Same shared-library mode | Execute on x86_64 emulator/device |
| arm64-ios-star | Apple Silicon, full Xcode; iOS 15.0+ | Static v8_monolith, JITless/lite, no WebAssembly | Unsigned App compile/link |
| arm64-ios-simulator-star | Same host/Xcode/target | Same static mode | Execute in iPhone simulator |

Both Release and Debug are validated. Pointer compression and sandbox are enabled
on all targets. ICU data and startup snapshots are embedded. Physical-device
behavior, signing and application-store acceptance are outside these CI checks.

## Build

Install Git, CMake 3.24+ and Ninja. Source builds require access to Chromium/Google
downloads and substantial disk space and build time. Commands run from the repo root:

```sh
# Windows
cmake -DTRIPLET=x64-windows-star -P scripts/build-v8.cmake
# Apple Silicon Mac
cmake -DTRIPLET=arm64-osx-star -P scripts/build-v8.cmake
cmake -DTRIPLET=arm64-ios-star -P scripts/build-v8.cmake
cmake -DTRIPLET=arm64-ios-simulator-star -DSIMULATOR_UDID=<uuid> -P scripts/build-v8.cmake
# Linux: set ANDROID_NDK_HOME; runtime tests also need adb and an emulator
cmake -DTRIPLET=arm64-android-star -P scripts/build-v8.cmake
cmake -DTRIPLET=x64-android-star -DANDROID_SERIAL=emulator-5554 -P scripts/build-v8.cmake
```

| Option | Meaning |
| --- | --- |
| CONFIGURATION=Release or Debug | Build one configuration; default is both |
| JOBS=4 | Compilation parallelism; default 4 |
| PRINT_ARGS=ON | Print GN arguments without downloading/building |
| SKIP_SYNC=ON | Reuse an already synchronized checkout for the same host/target |

Pass these with `-D`. Do not skip synchronization after changing platform dependencies.
A checkout lock protects the shared gclient tree; build one triplet at a time locally.

In Actions, **Build V8 13.6** is manual. Twelve jobs build six targets in two
configurations. Simulator builds upload candidates; separate execution jobs promote
them only after a passing per-launch result. Six package jobs merge the validated
Release/Debug pairs. Use **Re-run failed jobs** for transient failures.

Fixing consumer tests or the simulator controller does not require a V8 rebuild
when a complete successful SDK set already exists. Use **Validate existing V8 SDKs**;
details and source selection are in the [release guide](v8-release.md).

## Artifacts

Merged output:

```text
out/v8/<triplet>/star-v8-<version>-<triplet>-<linkage>-sdk.zip
```

`linkage` is `static` for iOS and `shared` elsewhere. Each ZIP has a SHA-256
sidecar. Single-configuration archives append `-release` or `-debug` to the
basename and reside under the corresponding configuration directory.

To merge separately built configurations, place their ZIPs and sidecars in
`<inputs>/Release/` and `<inputs>/Debug/`:

```sh
cmake -DTRIPLET=x64-windows-star -DINPUT_DIR=<inputs> -P scripts/v8/merge-sdk.cmake
```

Merging checks identities, shared files and checksums without rebuilding libraries
or rerunning consumers. Candidates without successful simulator execution are not
release inputs. SDKs include configuration headers, libraries, licenses and provenance;
there are no separate V8 runtime/symbol packages, XCFrameworks or AARs.

## Consume

Verify and extract the SDK. Match its architecture, platform, deployment target,
C++ standard library and Windows CRT:

```cmake
find_package(V8 CONFIG REQUIRED PATHS "${STAR_V8_SDK}/share/v8"
    NO_DEFAULT_PATH NO_CMAKE_FIND_ROOT_PATH)
target_link_libraries(your_target PRIVATE V8::V8)
```

The imported target supplies C++20, `V8_GN_HEADER`, pointer-compression/sandbox
macros, import definitions and configuration-specific paths. Select Release/Debug
with `CMAKE_BUILD_TYPE` or `--config`; never mix generated configuration headers.

Shared SDKs include component dependencies such as ICU, zlib and Abseil.
Deploy every file in `V8_RUNTIME_FILES_RELEASE` or `V8_RUNTIME_FILES_DEBUG`:
Windows DLLs are under `bin/` and `debug/bin/`; macOS/Android shared libraries
are under `lib/` and `debug/lib/`. Android preserves GN's `.cr.so` names and
bundles the matching NDK `libc++_shared.so`. Windows CRT/debugger DLLs are not bundled.

Desktop tests deploy beside the executable (macOS uses `@loader_path`).
Android deploys the same runtime set through adb; iOS links the static library
into the App. [Consumer tests](../tests/v8/CMakeLists.txt) check the V8 version,
JavaScript, ArrayBuffer and Intl against a relocated SDK.

## Patch rationale

Project patches live in [patches/v8](../patches/v8), with build arguments in
[args.cmake](../scripts/v8/args.cmake).

- Generated-header and cppgc fixes expose configuration macros to the right targets.
- iOS host generators stay static, including Debug, alongside target monolith builds.
- Android NDK builds explicitly link the matching libunwind with private symbols.
- Windows Abseil exports come from actual objects; inline-export fixes provide
  the DLL symbols required by MSVC consumers.

Preserve these constraints when upgrading V8. Original tool revisions and
build metadata remain embedded in every reused SDK.
